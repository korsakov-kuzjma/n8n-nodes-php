## Установка

Следуйте [инструкции по установке](https://docs.n8n.io/integrations/community-nodes/installation/) в документации community-нод n8n.

Коротко:

1. В вашем экземпляре n8n откройте **Settings → Community nodes**.
2. Выберите **Install a community node**.
3. Введите имя пакета: `n8n-nodes-php`.
4. Согласитесь с рисками использования community-нод и подтвердите установку.

Только self-hosted. Нода не работает в n8n Cloud, потому что требует локального бинарника PHP.

### Требования

- Self-hosted экземпляр n8n
- [PHP](https://www.php.net/) CLI, установленный **на той же машине**, где работает n8n, и доступный в `PATH`:

```bash
php -v
```

## Операции

- **PHP Execute**: выполняет произвольный PHP-код и возвращает результат.

Нода передаёт ваш код в стандартный поток ввода интерпретатора PHP (ничего не пишется на диск), а полезную нагрузку воркфлоу отправляет через отдельный дополнительный канал. После выполнения нода разбирает stdout:

- Если stdout — валидный JSON, он возвращается как структурированные данные (по одному item на элемент массива, если корень — массив).
- Иначе вывод оборачивается в `{ "output": "<текст>" }`.
- Непойманные фатальные ошибки, таймауты и исчерпание памяти возвращаются как типизированные ошибки (или кладутся как `{ "error": ... }`, когда включён *Continue On Fail*).

### Способ передачи данных

Выберите, как данные текущего item попадают в скрипт, через **Data Injection Method**:

- **STDIN** (по умолчанию): JSON текущего item передаётся в процесс по отдельному каналу и доступен как готовые PHP-переменные — читать и декодировать ничего не нужно.
- **Handlebars (Legacy)**: подстановка значений в код выражениями n8n вида `{{ $json.email }}` до выполнения.

Внутри скрипта всегда доступны:

| Переменная | Содержимое |
| ---------- | ---------- |
| `$n8nInput` | JSON текущего item как ассоциативный массив |
| `$n8nItems` | Все входящие items как массив ассоциативных массивов |
| `$n8nContext` | Метаданные воркфлоу: `nodeName`, `nodeId`, `workflowId`, `workflowName`, `executionId`, `runIndex`, `mode` |

### Режим выполнения

- **Run Once for Each Item** (по умолчанию): скрипт выполняется для каждого входящего item; каждый результат связывается со своим исходным item.
- **Run Once for All Items**: скрипт выполняется один раз для всех items (`$n8nItems` содержит их все). Если скрипт вернул столько же элементов вывода, сколько было входных items, они связываются 1:1; иначе все результаты привязываются к первому item.

### Опции

| Опция | По умолчанию | Описание |
| ----- | ------------ | -------- |
| Timeout (Seconds) | `30` | Максимальное время выполнения. При таймауте процесс сначала получает SIGTERM и принудительно завершается только через 2 секунды. |
| PHP Binary Path | `php` | Путь к бинарнику PHP CLI, например `/usr/bin/php8.3`. |
| Strict JSON Mode | выкл | Завершаться ошибкой, если вывод не парсится как JSON, вместо оборачивания в `{ output }`. |
| Composer Autoload Path | пусто | Подключает `vendor/autoload.php` через `auto_prepend_file`; предупреждает вместо падения, если файла нет. |
| Memory Limit (MB) | `128` | Передаёт `-d memory_limit=<n>M`; превышение даёт понятную ошибку о лимите памяти. |
| Security Level | Restricted | См. [Безопасность](#безопасность). |
| Result Cache TTL (Seconds) | `0` (выкл) | Повторные идентичные запуски в пределах окна возвращают закешированный результат без запуска PHP. |

Захватываемые stdout и stderr ограничены 10 МБ каждый; при превышении процесс завершается и возвращается ошибка.

### Дополнительные файлы

Через **Additional Files** можно передать вспомогательные скрипты рядом с основным кодом. Файлы записываются в директорию песочницы до запуска, а PHP-процесс стартует с этой директорией как рабочей, поэтому обычные include работают сразу:

```php
<?php
require 'helpers.php';
echo json_encode(["result" => my_helper(21)]);
```

Имена файлов должны быть простыми (`буквы-цифры._-`); содержимое — любой PHP.

## Учётные данные

Не требуются. Нода использует локально установленный PHP.

> **Примечание о безопасности:** выполняемый код работает с правами процесса n8n. Используйте только собственный доверенный код и никогда не отдавайте эту ноду недоверенному вводу без валидации.

## Использование

### Верните JSON из скрипта

Выведите валидный JSON через `echo`, чтобы получить структурированные items:

```php
<?php
$data = [
    ["status" => "success", "time" => time()],
    ["status" => "success", "time" => time() + 1],
];
echo json_encode($data);
```

Результат: два items с полями `status` и `time`.

### Обычный текстовый вывод

```php
<?php
echo "Привет из PHP в " . date('H:i');
```

Результат: один item `{ "output": "Привет из PHP в 14:05" }`.

### Работа с текущим item ($n8nInput)

При способе *STDIN* (по умолчанию) текущий item приходит уже декодированным в `$n8nInput` — безопасно для кавычек и любых спецсимволов:

```php
<?php
echo json_encode(["status" => "ok", "data" => $n8nInput]);
```

Для входящего item `{ "email": "a\"b@c.ru" }` результат:

```json
{ "status": "ok", "data": { "email": "a\"b@c.ru" } }
```

### Обработка всех items за один запуск (batch)

Переключите **Execution Mode → Run Once for All Items** и обойдите `$n8nItems` циклом:

```php
<?php
$out = [];
foreach ($n8nItems as $item) {
    $out[] = ["email" => $item["email"], "score" => strlen($item["email"])];
}
echo json_encode($out);
```

Если вернуть по элементу на каждый входной item, связь 1:1 сохранится.

### Использование контекста воркфлоу

```php
<?php
echo json_encode([
    "workflow" => $n8nContext["workflowName"],
    "run" => $n8nContext["runIndex"],
]);
```

### Доступ к входящим данным через выражения (legacy)

Установите **Data Injection Method → Handlebars (Legacy)** и используйте стандартные выражения n8n в поле кода, например `{{ $json.email }}`, чтобы подставить значения до выполнения:

```php
<?php
echo json_encode(["greeting" => "Привет, {{ $json.name }}"]);
```

> Примечание: подставленные значения вставляются в PHP-код как есть; кавычки внутри данных могут сломать код. Предпочитайте STDIN.

## Безопасность

Опция **Security Level** управляет степенью изоляции выполняемого кода:

| | Restricted (по умолчанию) | Unrestricted |
| - | ------------------------- | ------------ |
| Shell-функции (`exec`, `shell_exec`, `system`, `passthru`, `popen`, `proc_open`, …) | отключены через `disable_functions` | разрешены |
| Сетевые примитивы (`fsockopen`, `stream_socket_*`, `curl_init`/`curl_exec`, `socket_create`, …) | отключены через `disable_functions` | разрешены |
| Статический анализ кода до запуска | блокирует shell-вызовы, бэктики и загрузку URL (в основном коде **и** дополнительных файлах) | пропускается |
| Доступ к удалённым файлам (`allow_url_fopen` / `allow_url_include`) | отключён | как в php.ini |
| Область доступа к файлам | директория песочницы (+ vendor Composer, если задан) | без ограничений |
| Пользователь ОС | переход на `nobody`, когда n8n запущен от root | пользователь процесса n8n |
| Рабочая директория | `/tmp/n8n-php-sandbox` | `/tmp/n8n-php-sandbox` |
| Лимиты памяти / времени / вывода | действуют | действуют |

Restricted рассчитан так, чтобы даже недоверенный код не мог выбраться в shell или прочитать произвольные пути; Unrestricted используйте только для полностью доверенных скриптов.

## Миграция с 1.x

- Замените `json_decode(file_get_contents('php://stdin'), true)` на `$n8nInput`.
- Если вы полагались на `__FILE__`/`__DIR__`, указывающие во временный файл: теперь они указывают на `Standard input code`.
- Старый чекбокс **Safe Mode** стал выпадающим списком **Security Level**: `true` превращается в *Restricted*, `false` — в *Unrestricted*; воркфлоу, где опцию ни разу не сохраняли, теперь работают в **Restricted** и будут блокировать shell-функции, пока вы явно не переключите их на *Unrestricted*.
- Скалярные JSON-корни сохраняют тип (`42` вернёт `{ "output": 42 }` числом).

## История версий

### 2.0.2

- Технический релиз без изменения поведения ноды: CI-воркфлоу используют `actions/checkout@v7`; обновлены dev-инструменты (`release-it` 21, транзитивный `ip-address` 10.5).

### 2.0.1

- Релиз исправлений: статический анализ теперь покрывает **дополнительные файлы** и `phpCode`, вычисленный для каждого item (режим Restricted).
- Расширен runtime-список блокируемых функций в Restricted mode сетевыми примитивами (`fsockopen`, `stream_socket_*`, `curl_*`, `socket_*`).
- Усиление песочницы: атомарная запись без symlink-гонок, очистка временных файлов, проверка владельца каталога под root; конверт фатальных ошибок переживает невалидный UTF-8.
- Кэш результатов ограничен 1 МБ на запись и хранит сырой вывод.

### 2.0.0

- **Ломающее:** PHP-код передаётся через STDIN (выполнение полностью в памяти); данные приходят переменными `$n8nInput` / `$n8nItems` / `$n8nContext` вместо `php://stdin`; `__FILE__`/`__DIR__` указывают на `Standard input code`.
- **Ломающее:** Safe Mode заменён списком **Security Level** (*Restricted* по умолчанию / *Unrestricted*); старые значения `safeMode` маппируются автоматически.
- **Execution Mode**: per-item или batch (один процесс на все items) с корректным `pairedItem`.
- Усиленная песочница: расширенный `disable_functions`, запрет удалённых файлов, `open_basedir`, статический анализ до запуска, переход на `nobody` под root.
- Типизированная иерархия ошибок, включая разбор фатальных ошибок (shutdown envelope) и определение OOM; метрики (`executionTimeMs`, `peakMemoryUsageMb`, `exitCode`) логируются и прикрепляются при Continue On Fail.
- Опция **Result Cache TTL** и коллекция **Additional Files** (рабочая директория песочницы).
- Опции валидируются zod (включён в сборку, рантайм-зависимостей нет); путь к автозагрузчику Composer предупреждение вместо падения.

### 1.0.0

- **Data Injection Method**: JSON текущего item передаётся в PHP через STDIN по умолчанию — безопасно для любых символов, экранирование не требуется. Подстановка выражениями n8n осталась доступна как *Handlebars (Legacy)*.
- Опция **PHP Binary Path** — путь к конкретному бинарнику CLI (по умолчанию `php`).
- **Strict JSON Mode**: ошибка при невалидном JSON вместо оборачивания в `{ output }`.
- Опция **Composer Autoload Path**: подключает `vendor/autoload.php` через `auto_prepend_file`, если файл существует.
- **Safe Mode**: отключает исполняющие функции (`exec`, `shell_exec`, `system`, `passthru`, `popen`, `proc_open`) и ограничивает доступ к файлам временной папкой скрипта (`open_basedir`).
- Опция **Memory Limit (MB)** (по умолчанию 128) через `-d memory_limit`.
- Плавное завершение по таймауту: сначала SIGTERM, SIGKILL — только через 2 секунды.
- Захватываемые stdout/stderr ограничены 10 МБ с понятной ошибкой при превышении.
- Рефакторинг: вынесено управление процессом и парсинг вывода; добавлен набор тестов Jest.
- Надёжное заполнение `pairedItem` у каждого возвращаемого item.
